## Notes for a reviewer

- Mutants that touch the same source file ran in separate batches (1 to 6), so no mutant hid another: round3:169 and round8 (both `effectivePrices`) are in batches 2 and 1; the two `checks.ts` mutants in batches 1 and 2; the two `setup-agent-run.ts` mutants in batches 1 and 2.
- round4: the first batch-1 run also carried the round8 mutant (a 44 s delay inside `effectivePrices`, which the refresher calls), so its failure there was a price assertion in the warm-up, not the ratio. The result above is the clean batch-4 run, where the quadratic mutant fails the ratio (`expected 39.8 ... less than or equal to 30`; the same mutant measured 42.7 in Cloud).
- The round4 quadratic mutant adds `n*n` multiply-and-log steps in `fetchLiteLLM` (about 10 s at 20,000 rows, 0.1 s at 2,000). A real O(n^2) pass over a heavier loop body is slower still, so 30x is a floor for what is caught, not the edge.
- prompt-locations: the first mutant went into `packages/contracts/src`, but that test imports the BUILT package (`@agentx/contracts` resolves to `packages/contracts/dist`), so it survived (a mutant in the wrong file, not a weak test). The result above is the same mutant applied to `dist/prompt-locations.js` (restored from a backup copy afterwards; `dist` is ignored by git).
- e2e-midstep2-end-to-end:185 fails with `E2EModelChannelError` rather than the elapsed assertion: the product's own session-sync bound refuses a header read that is 9 s late before the test's 9.5 s bound is reached. So the product bound is tighter than the widened test bound; the test still fails, which is the point.
- round8: the first test fails by the bound (88 s against 3 s: the 44 s delay runs twice), the second by the 60 s test timeout. e2e-executor-run:191 fails by the bound (53 s against 50 s). setup-l9-shell-prepare:148 fails by the 60 s test timeout (40 s delay on top of the real run). All are timing failures.
- stage-selection-adversarial is nightly-only (`ROVARA_NIGHTLY_TESTS` / vitest.nightly.config.ts); it was run under that config. devcontainer.test.ts (3 bounds) and the chromium tests need docker or a browser and were not run here.
