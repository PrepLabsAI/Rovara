# Static prompt changes (TE-F4)

This additive M2 / 0.5.19 contract detects changes in supplied source text. It has no production callers yet. TE-F3 and TE-F10 should read `PromptChangeReportSchema`, `detectPromptChanges`, `detectPromptChangesInDiff`, `promptChangesNeedEval` and `promptChangesNeedSideBySide`, exported from the contracts barrel.

```ts
const { report } = detectPromptChanges({
  files: [{ path: "prompts/summary.prompt", before: baseText, after: headText, wholeFile: true }],
});
const decision = promptChangesNeedEval(report); // { needed, reason }
```

`detectPromptChangesInDiff(diffText)` reads Git/workspace unified diffs, including quoted/octal filenames, both rename names, new/deleted/binary files, newline markers and CRLF or CR line endings. Each hunk retains its own boundaries and line offsets. The whole-file entry point ignores caller-supplied hunk metadata, so it cannot bypass side caps; overflowing parsed line offsets are refused. It cannot supply whole-file coverage, even for an added file. Whole-file callers must explicitly pass `wholeFile: true`; missing before/after text needs the corresponding `added`/`removed` status. Hunkless prompt renames carry null content fingerprints rather than invented empty-file hashes.

The result is `{ report, stats? }`. Opt in with `{ stats: true }`; stats contain only numeric work/byte/file counts and are outside the strict report schema. Serialize only `report` into evidence. `none_found` requires complete coverage. Unreadable or capped input is `incomplete`, including when some changes were found. The one exception is a truncated item list: its status remains `changes` as required by v1, and its coverage still records any incompleteness. Both selectors conservatively return `{ needed: true, reason: "incomplete" }` for incomplete coverage. The side-by-side selector uses full counts, including changes beyond the first 500 items.

The report contains no prompt, system instruction, tool schema, endpoint or diagnostic text. Values are SHA-256 fingerprints. The explicit Q1 exception permits bounded ordinary repository paths in `path`/`oldPath` only; they are metadata. The path allow-list is letters/numbers, spaces, underscore, dot, slash and hyphen, with a non-space first character, no leading `---`, and at most 512 UTF-16 units. Hidden, control, bidi and variation-selector characters and markup are refused to `path_refused`; `pathFingerprint` and `oldPathFingerprint` identify refused names. Consumers still render paths through their inert-text function. Valid model names use F0a's **MODEL_NAME_PATTERN**, not its broader echo pattern. Only finite numeric settings and the schema's fixed `SETTING_ENUM_WORDS` may otherwise be echoed. The strict discriminated union does not admit before/after fields on other kinds. Errors and refusals use fixed codes and sentences.

The rules are in `src/prompt-change-rules.ts`:

- Prompt extensions: `.prompt`, `.prompty`, `.dotprompt`, `.jinja`, `.jinja2`, `.j2`, `.hbs`, `.handlebars`, `.mustache`; `*.prompt.md`; `.txt` names containing `prompt` or `system`; and `.md/.txt/.yaml/.yml/.json/.toml` below `prompt`, `prompts` or `system-prompts` folders. Prompt files are fingerprinted as a whole and not scanned a second time as code.
- Code: JS/TS (`js/jsx/ts/tsx/mjs/cjs/mts/cts`) and Python (`py/pyi`), with single/double/triple strings, raw/f strings, templates, balanced interpolation holes, escapes and continuations. It recognizes the brief's literal prompt/system/content, positional generation/template, model-helper, setting and tool-schema patterns. Dynamic expressions, aliases, imports of prompt values and variable resolution are ignored; no code is executed. Settings and content/input need an SDK import/require, recognized model prefix or an AI folder (`prompts/models/llm/ai/agents`); input additionally needs a known SDK-call context. A content field needs a role in the same object; system roles retain their kind independent of key order.
- Config: JSON/YAML/YML/TOML/env/INI token or line scanning, including YAML block scalars. No YAML parser, alias/merge expansion or untrusted JSON object construction. Model/setting aliases and enum words are explicit lists, not fuzzy matching. YAML aliases/merges, malformed strings/containers, unsupported executable formats and excessive nesting yield `unreadable_diff`, the fixed v1 reason for unreadable source as well as diff syntax. Ordinary `.md/.txt/.rst/.adoc/.csv/.svg/.css/.html` files outside prompt rules are not executable-source inputs.
- Model prefixes are owned here, all marked **UNVERIFIED** against vendor SDK runs. Unknown names under model keys retain `family: null`. Catalog hosts come from F0a; exact DNS tokens count, suffix lookalikes do not. A host listed under multiple families has a null family hint. Endpoints are never echoed.

Fingerprints remove Unicode format/bidi characters and collapse whitespace, including line wraps. Tool/structured-setting values join lexical tokens, normalizing string content separately so layout around punctuation does not matter. This is deliberately lexical, not a semantic equivalence proof. Interpolation text is balanced and fingerprinted without evaluating or resolving it. Equal fingerprints are matched with queues first, then remaining equal key paths pair by ordinal. IDs hash a domain tag, kind, file hash and line-independent anchor. Rename items use the after path. Hunk offsets affect `line` but not IDs.

Default caps are 2,000 files, 1 MiB per file side, 32 MiB total including path metadata, depth 64, 512 path characters and 500 output items. Options may only lower scan caps. Too many whole-file inputs, duplicate paths or an excessive total refuse the batch rather than choosing an order-dependent prefix. Counts and the digest cover all detected items even when the displayed list is truncated. File-side limits check UTF-8 bytes. Very large strings first fail a cheap UTF-16 lower-bound check. Paths and ancestor identities are hashed once; queues never shift arrays. Scanning is iterative with no input-dependent recursion. Output sorting compares bounded keys; the finite byte/item limits bound comparison work. The work counter charges character passes, tokens, hashing, bounded ancestor visits and sorting comparisons; tests enforce `steps <= 2048 * (bytes + 1) + 100000` and median N/4N timing bounds. Oversized 4 MiB individual sides intentionally exercise refusal; a separate four-file case exercises 4 MiB of actual scanning.

This replaces the plan block's recorded-request ledger comparison for this lane. The ledger comparison, its F2/F3 dependencies and original 0.5.20 scheduling are deferred; no ledger or model call is built here. Deferred syntax includes other programming languages, semantic data flow, computed property names, YAML anchors/merges and nonliteral expressions. A new language or grammar needs explicit tests and coverage rules before it can claim complete scanning.

The runtime-built fixtures contain no credential-shaped literals. All detector tests deny fetch and sockets. The no-callers test scans production packages; tests themselves are expected consumers.
