# Repository dependency facts

`EvidenceRaw.repositoryEdges` is optional. When a local multi-repository task saves evidence and the worker finds at least one dependency edge, it records `{ edges, notes }` alongside existing evidence. Edges alone never create an evidence file. Old records without this field keep their existing shape and bytes.

Each edge has `consumer` and `provider` repository IDs, `language` (`node`, `go`, `python`, `maven`, or `gradle`), and `source` (`base`, `candidate`, or `both`). There are at most 64 distinct edges, no self-edges, and at most eight fixed-word notes. Cycles are recorded as distinct directed edges; MR3 decides merge order. MR3 must check repository IDs against the task's pull requests before using the facts.

Edges are the union of the manifests at the workflow base commits and the candidate working files. A dependency removed from the candidate remains recorded with source `base`. **MR3/MR2b must NEVER use an edge's absence from the candidate to skip or narrow tests.** Every check continues to run in full in this lane.

**MR1 is off (`MULTI_REPO_CHECKS_LIVE = false` in `packages/worker/src/multi-repo-supplier.ts`).** Every check round runs exactly as before, in the shared workspace with the ordinary runners; no check root or report directory is made. The edges are derived only when the round's evidence is saved, from the base and the candidate as they stand after the round, within the round's remaining budget (the time is taken from the baseline's share). No edge, a refused derivation or an exhausted budget records nothing. MR1's check root is a checkout of the candidate tree and has none of the workspace's git-ignored installed dependencies (`node_modules`, `.venv`), so ordinary checks would fail there; the MR1-LIVE lane turns the constant on once the root mirrors those folders with link safety.

With the constant on, the worker derives once, lazily, under the first check round's existing timeout and abort/join guard (a derivation that runs out of that budget is derived again by the next round), and a round with edges runs in MR1's check root. Single-repository, nightly, non-local and explicitly injected scopes retain their existing selection path. No-edge automatic rounds call the ordinary runners, create no check root or report directory, and emit no repositoryEdges field.

Automatic derivation supports root Node package dependency maps, Go module requirements, and conservative Python declarations. Python reads project name/dependency string arrays in `pyproject.toml`, literal metadata (`name`, `version`, `description`) and `[options].install_requires` in `setup.cfg`, and a literal `from setuptools import setup; setup(name=..., version=..., description=...)` form (with a newline instead of a semicolon) in `setup.py`. It never executes Python. Root `requirements*.txt` and `requirements*.in` files accept ordinary named requirements and sibling local/editable paths. Duplicate declarations, dynamic declarations, aliases, includes and unsupported syntax refuse the derivation as a whole with fixed words. Maven and Gradle remain tested separately. No lockfiles, nested manifests or installed package copies are read.

Limits are shared across the base and candidate: 32 repositories, 64 union edges, 2 MiB of manifest bytes within a 2.5 MiB total byte budget (including directory listings), 704 manifest reads, 4,096 root directory entries and 32,768 dependency items. Root inventories are bounded across every repository and both sources; an overflow refuses the whole derivation. Ambiguous provider names, malformed/unreadable manifests and exceeded limits yield no automatic scope; they do not change check verdicts. Manifest content and parser errors are never put into notes.

The contracts field must ship before or together with the emitting worker: an older strict engine schema rejects records containing it. Code ships worker and contracts together. The Cloud worker mirror, non-local execution proof, cross-repository selection/combined baseline (MR2b), merge ordering (MR3), and CI wording (MR4) are separate lanes. This behavior change must not merge before the controller's re-pin carries it.
