# Data Model: Create Pull Request

## PullRequestRequest

Fields: `requestId`, `repository`, `title`, optional `body`.

- `requestId` is a UUID and participates in owner/workspace idempotency.
- `repository` is a registered repository name, not a URL or path.
- `title` is trimmed, contains no control characters, and is 1–256 characters.
- `body` is at most 32 KiB and contains no NUL character.
- The payload hash includes every field. Same request ID and hash returns the original operation;
  the same request ID with another hash is an idempotency conflict.

## PublicationOperation

An existing `Operation` with kind `publish`, the selected repository, deterministic branch, and
normal fence/status fields.

Branch: `agentx/<operation-id>`. It is generated by the broker and never accepted from the client.

States use the existing operation lifecycle:

```text
ACCEPTED -> DISPATCHING -> RUNNING -> SUCCEEDED
                                 -> FAILED
                                 -> CANCEL_REQUESTED -> CANCELLED | INTERRUPTED
```

The workspace transitions `READY -> BUSY -> READY | UNHEALTHY` under its existing conditional
writer fence. No task or second publication may acquire the checkout concurrently.

## PublicationCheckResult

Fields: check index, cwd, executable, exit code, bounded stdout/stderr, start/end timestamps,
and outcome (`passed`, `failed`, `timed_out`). Results are non-secret and included in the terminal
publication result; large output follows existing artifact bounds.

## PullRequestResult

Fields: `repository`, `number`, `url`, `headBranch`, `baseBranch`, `commit`, `checks`, and
`reconciled`.

- `number` is a positive repository-local pull-request number.
- `url` must be a canonical HTTPS URL under the configured GitHub host/account/repository.
- `headBranch` equals the broker-generated publication branch.
- `baseBranch` equals the registered default branch.
- `commit` is the full published Git object ID.
- `reconciled` records whether an existing matching pull request was returned after retry.

Terminal results are immutable and contain no access tokens, authorization headers, or private key.

## RepositoryGrantScope

Extends the existing exact repository scope with access `clone | push`.

- `clone` resolves only a contents-read credential.
- `push` resolves only a contents-write credential and is issued only for a publish operation.
- The exchange must match workspace ID, operation ID, credential reference, exact URL, and access.

## ExternalPublication

The observable GitHub state identified by repository, deterministic head branch, configured base
branch, commit, PR number, URL, and open/closed state. It is queried during retries and is not a
credential. AgentX never assumes a timeout means the external side effect failed.
