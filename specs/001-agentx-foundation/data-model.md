# AgentX Data Model

## ProjectDefinition

Fields: `schemaVersion`, `name`, `revision`, `controlPlaneUrl`, `auth`, `environment`,
`repositories`, `setup`, `readiness`, `orchestratorInstructions`.

- `schemaVersion` is exactly `1`; unknown versions and unknown keys are rejected.
- `name` and repository `name` match `^[a-z][a-z0-9-]{0,62}$`.
- `revision` is a positive integer; prepared instances pin that revision.
- `environment.image` is an OCI reference ending in `@sha256:` followed by 64 lowercase hex digits.
- Repository paths are unique relative POSIX paths; absolute paths, `..` segments and overlaps
  are rejected; resolved paths and symlinks must remain inside the workspace.
- Repository initial refs are full commit IDs; at least one repository is required.
- `controlPlaneUrl` uses HTTPS; loopback HTTP is allowed only in explicit local test mode.
- Commands use executable/argument arrays with repository-relative cwd and positive timeout.
- Secret values and developer-specific workspace/session identifiers are forbidden in shared definitions.
- Auth contains issuer, client ID and audience metadata; tokens are not stored in project files.

The local definition selects and describes a project. The broker's admin-registered revision
is authoritative; a client-modified definition cannot grant access or change the remote image.

## Owner / ProjectMembership

Owner key derives from verified issuer plus subject, never a display name or request-body owner.
Membership associates owner, project and role (`developer` or `administrator`). Administrator
operations may name a target owner only after authenticated role and project-scope checks.

## WorkspaceInstance

Fields: UUID `id`, `ownerKey`, `projectName`, `projectRevision`, `environmentDigest`,
`runtimeArn`, `endpointQualifier`, internal UUID `runtimeSessionId`, `deploymentMode`, optional
`capacityProviderArn`, `rootPath`, `status`, `preparationManifest`, `activeOperationId`, `fence`,
timestamps.

- `rootPath` is `/mnt/workspace`; each repository lives beneath `/mnt/workspace/repo/`.
- At most one default instance exists for `(ownerKey, projectName)` using conditional creation.
- Runtime session IDs and routing fields are server-owned and excluded from developer requests.
- `deploymentMode` is `instances-ebs` or `demo-microvm`. A capacity-provider ARN is required
  only for `instances-ebs` and forbidden for `demo-microvm`; the latter binds managed storage
  to the runtime session ID and is subject to the documented demo retention limits.
- A mount uses `/mnt/<single-subdirectory>`; no cross-owner shared writable volume is permitted.
- Environment revision, digest and endpoint are immutable during normal resume.

States: `PREPARING -> READY | PREPARATION_FAILED`; `READY -> BUSY -> READY | UNHEALTHY`;
`READY -> STOPPED -> RESUMING -> READY | UNHEALTHY`. Preparation retry may move
`PREPARATION_FAILED -> PREPARING` only with the same recorded definition.
Deleted/migrating states are reserved for explicit later administrator workflows.

## Conversation

Fields: UUID `id`, `workspaceId`, `sessionFile`, created/updated timestamps.
`sessionFile` is generated by the server beneath `/mnt/workspace/agent-sessions/` and never
accepted as an arbitrary client path. Many conversations can reference one workspace.
Starting a conversation does not alter repository files. Only one run mutates the workspace.

## Operation

Fields: UUID `id`, `workspaceId`, `conversationId` when applicable, `kind`, `requestId`,
`payloadHash`, `status`, `fence`, heartbeat, timestamps, result/error and event cursor.

- Kinds: `prepare`, `task`, `resume`, `stop`, `cancel`.
- Request IDs are UUIDs, unique within owner/workspace; same ID plus same payload returns the
  existing operation; same ID plus different payload returns `IDEMPOTENCY_CONFLICT`.
- Task prompt is non-empty UTF-8 text, at most 64 KiB before encoding.
- States: `ACCEPTED -> DISPATCHING -> RUNNING -> SUCCEEDED | FAILED | CANCELLED | INTERRUPTED`;
  `CANCEL_REQUESTED` can precede a terminal result; setup may fail before RUNNING.
- Terminal results are immutable. Cancellation is cooperative and does not imply rollback.
- Lease loss never authorizes a second writer without old-worker termination/acknowledgment.
- Status/outbox metadata is broker-owned. Worker journal records acceptance before starting pi.

## Event / Artifact

Event fields: operation ID, monotonically increasing sequence, timestamp, type and bounded payload.
Types: progress, tool_start, tool_end, result, error, lifecycle. Polling uses an opaque cursor.
Persist complete messages/tool outcomes; batch text deltas rather than one database write per token.
Artifacts hold large diffs/logs/test results, with owner/workspace/operation linkage and
object-specific short-lived download grants. Logs redact tokens and credential-bearing URLs.
Shared storage permissions must not let one coding worker enumerate other owners' data.

## Preparation manifest

Stored on EBS: project revision/image digest, repository commit IDs, completed setup steps,
readiness results, creation identity, and completion marker. Write step completion atomically;
retry only unfinished safe steps. Refuse mismatched revisions and never reset an existing checkout.
